# 2026-09-23 성능 조사

사용자 증상은 스킬 사용 순간뿐 아니라 평소 이동·정지 중에도 끊기는 느낌이다. 조사 당시 게임과 QEMU는 실행 중이지 않아 실제 FPS나 병목 위치를 측정하지 못했다. 아래 수치는 원인 확정이 아닌 코드·리소스에서 확인한 부하 근거다.

- 렌더러는 `CreateDevice`에 `D3DCREATE_SOFTWARE_VERTEXPROCESSING`(0x20)을 강제한다. 실제 Render.dll 0x1001ECE0 및 `W3DScene.cpp`와 일치한다.
- 네이티브 모델 버퍼는 삼각형 코너마다 정점을 펼친다. 현재 H03 활 26,580삼각형은 79,740정점/프레임이며 이전 모델 10,328삼각형(30,984정점)의 2.57배다. 정지 중에도 장착 무기를 매 프레임 그린다. 활 자체의 bone skinning 문제가 아니라 rigid mesh의 정점 처리 부담이다.
- 메테오 한 회 최대 47 draw, 약 13,476삼각형. 4초 간격 중첩 최대 68 draw. 개별 리소스 복잡도는 HEAD와 같다. 대상 사망 시에도 끝까지 보이도록 한 만큼 조기 종료되던 경우보다 화면에 오래 남는다.
- 저장된 얼음 배치 확장으로 최대 draw는 HEAD 183에서 213, 삼각형은 6,442에서 6,928로 늘었다. 색·크기·배치 설정은 사용자 저장값이므로 이번 조사에서 줄이지 않았다.
- 말 불자국은 프레임마다 1개, 수명 1.76초, 입자당 2 draw다. 60fps 기준 약 106개/212 draw, 144fps는 약 254개/508 draw. 원본 입자 코드의 수명 만료 시 제거 경로는 존재하며 무한 누적이 확인된 것은 아니다. 실제 정지 시 발생 중단 여부는 게임 확인이 필요하다.
- 기존 스킬 미리보기는 일시정지·백그라운드에도 매 프레임 렌더링한다. 이것은 별도 프로세스의 추가 부하 후보이며 게임 병목으로 확정한 것은 아니다.

확인된 미리보기 낭비는 수정했다. 숨긴 탭은 Three의 animation loop와 소리를 중단하고, 표시된 일시정지 화면은 카메라 이동·감쇠 또는 설정 변경 시에만 그린다. `tools/verify_preview_idle.cjs`에서 실제 prototype 메서드를 실행해 일시정지 120프레임 0 draw, 카메라 반응, 재생 유지, 숨김 작업 중단, 복귀 시 시간 연속성을 검증했다. 로컬 preview.js에 반영했으며 이미 열어 둔 페이지에는 새로고침 후 적용된다. 이것만으로 게임 렉이 해결됐다고 판단하지 않는다.

위 수치는 수정 전 조사 기준이다. 이후 사용자가 선택한 06 장궁 제작과 함께 다음 개선을 적용했다.

| 대상 | 수정 전 | 수정 후 | 검증 |
| --- | --- | --- | --- |
| 장착 활 | 26,580삼각형 / 79,740 렌더 정점 | 5,148삼각형 / 15,444 렌더 정점(80.6% 감소) | 실제 MOD 재읽기, 닫힌 표면, 손 본·지면 간섭 검사 |
| 지옥마 불자국 | 유지되지 않는 상태 필드로 방출 차단; 통과 시 프레임마다 생성 | 실제 XY 이동으로 판정, 80ms 및 0.25거리 간격, 정지·텔레포트 방출 없음 | 기존 실패 재현, 15~240fps 경로, 스택·레지스터·타이머 순환 |

| 얼음 소리 객체 | 시전당 215개 | 5개 | 모든 SOUND/BLOWTIMING 보존 |

소리 객체가 없어진 활성 무음층은 실제 Engine→Sound 경로에서 매 프레임 가상호출 1회와 x86 명령 13개를 덜 실행한다. 무음 SoundObject의 Update3D 자체가 짧게 반환하므로 큰 오디오 병목을 없앴다고 주장하지 않는다. 마법이 없는 평소 프레임에는 이 개선 효과가 없다. `silent-magic-update-validation.json`에 480쌍의 프레임 검증 결과와 한계를 기록했다.

평소에도 장착 무기를 그리는 경로의 부담은 줄였지만, 전체 게임 FPS·프레임 지연은 실행 중 게임에서 측정하지 못했다. 렉의 유일한 원인이 확정되었거나 모두 해결되었다고 볼 수는 없다. 렌더러 hardware 처리 강제 전환, 프레임 제한 변경, 사용자 스킬 밀도 축소는 적용하지 않았다. 기존 프레임별 이동 로직 때문에 임의 프레임 제한은 효과 속도를 바꿀 수 있다.

무기 검수 브라우저도 정지 화면에서는 계속 그리지 않고, 회전/확대/화면 변경 때만 렌더링하도록 바꿨다. 숨긴 탭의 애니메이션도 중단한다.

좌클릭 동작도 확인했다. 실제 `OnMouseLClick`은 전역 `m_bCheckLMB`를 토글해 몹 선택과 공격을 번갈아 수행한다. 선택된 흑마법이 있으면 공격이 시전으로 이어진다. 기존 10106/10111 및 신규 19120~19123의 12개 조합에서 동일하며 신규 스킬만의 입력 데이터 오류는 아니다. 입력 방식 변경은 사용자 선택이 필요하다.
