# 2026-09-23 · 15개 무기 시안과 실시간 조절 수정

검·활·지팡이 각각 5개, 총 15개를 독립 ImageGen 호출로 새로 생성했다. 고결한 푸르름과 달의 실루엣을 중심으로 원화와 정확한 프롬프트를 보존했으며 [비교 갤러리](noble-moon-15/index.html)에서 종류별 필터·확대·선택을 지원한다. 이번 시안으로 게임 모델을 교체하지 않았다. [자산 검증](noble-moon-15/asset-validation.json)은 이미지 15개와 기존 보호 파일 59개, 설치된 검·활 파일 16개의 일치를 기록한다.

## 재현한 문제와 수정

이전 v7 검수는 응답과 저장 성공을 확인했지만, 슬라이더 연속 조절 시 화면 반응이 늦고 재생 시점이 돌아가는 문제를 놓쳤다. 실제 브라우저에서 헤븐 광량 변경이 약 2.3–2.5초 뒤에 표시됐으며 네 스킬 전체를 다시 계산하고 약 3.5MB를 전송했다. 재생 중 자산을 반영하면 0초로 되돌아가 적중 장면을 조절하기 어려웠다.

- 조절한 스킬만 생성·전송한다. 전체 저장·게임 적용은 기존 전체 컴파일 경로를 사용한다.
- 이미 읽은 메시·텍스처의 해시를 비교하고 달라진 자산만 전송한다. 동일 WTM의 PNG 변환은 제한된 크기의 캐시를 재사용한다.
- 연속 입력을 직렬 큐로 처리한다. 계산을 마친 중간 결과도 표시하고, 대기 중인 값은 해당 스킬의 최신값으로 합친다.
- 반영 직전의 재생 시각과 재생/일시정지 상태를 유지한다. 이미 지나간 발사음을 반복하지 않는다.
- 스킬마다 반영 중/반영 완료 표시와 실제 처리 시간을 표시한다.
- 로딩 중이거나 다른 입력이 유효하지 않아 보류된 변경도 기억하고, 정상 입력으로 돌아오면 함께 반영한다.

## 검증

[HTTP 회귀 결과](../skills140/live-preview-validation.json)는 단일 요청 약 0.22–0.40초, 변경 없는 텍스처·메시의 재전송 생략, 밝기가 바뀐 잔상 텍스처와 눈보라 메시의 실제 네이티브 자산 일치를 확인했다. 이 수치는 로컬 HTTP 처리 실측이며 모든 장치의 프레임 시간 보장은 아니다.

`tools/verify_live_preview.mjs`는 빠른 연속 입력, 최종값 유지, 다른 스킬의 처리, 보류된 변경 복구, 실제 `applyAssets`의 재생/정지 시각 보존을 검사한다. 모두 통과했다.

실제 브라우저에서 헤븐의 2.19초 정지 프레임 광량 1↔0.3 변경은 0.32–0.36초에, 얼음의 2.09초 정지 프레임 크기 1.5↔2.3 변경은 0.55–0.58초에 표시됐다. 재생 중 반영할 때 2.19→2.74초로 이어지고 0초로 복귀하지 않았다. 메테오 광량을 잘못 입력한 동안 변경한 얼음 값도 메테오 입력을 정상 복구하자 두 카드에 함께 반영됐다. 검사 후 모든 테스트값을 복원했고 저장된 색상·조절 설정 해시는 이전과 동일하다. 콘솔 수집 중 오류는 없었다.

화면 비교: [헤븐 광량 1](live-preview-heaven-bright.png) / [광량 0.3](live-preview-heaven-dim.png), [얼음 크기 1.5](live-preview-frost-size-1_5.png) / [크기 2.3](live-preview-frost-size-2_3.png). 상세 실측은 [검증 보고서](../skills140/live-preview-validation.json)의 `browser_checks`에 있다.

기존 56개 조절 항목과 저장 설정을 유지한다. 이 패널은 `--preview-only`로 실행되며 아버지용 게임 설치본·계정·DB·VM·실행 CMD를 변경하지 않는다. 실제 Direct3D 전투 검수는 이번 작업 범위에 포함되지 않았다.
