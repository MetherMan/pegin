# 수량 프로토콜 및 클라이언트 패치

포션(type 44)은 9999개, 웨폰/아머 카드(10193/10194)는 999개가 한 묶음입니다. 기존 컨테이너(type 43)는 99개입니다. 포션 104종의 서버 무게는 모두 0입니다.

구매 요청(69), 인벤 목록/삽입(60/43), 수량 갱신(115/256), 창고 목록/삽입(121/122)의 수량은 서버와 클라이언트 모두 WORD입니다. UI 항목은 기존 패딩을 사용해 구조 크기를 유지합니다. 구매 입력 제한도 9999입니다. 기존 개인상점 및 다른 서버 이동 패킷의 BYTE 필드는 유지하며, UI로 전달할 때 상위 바이트를 0으로 만듭니다. 해당 별도 거래 화면까지 9999개 일괄 거래를 지원한다고 주장하지 않습니다.

`tools/patch_stack_client.py`는 원본 명령어를 검사하고 `.cache/stack16-client`에 결과를 만듭니다. 현재 배포본을 입력해도 여기의 undo 정보로 이전 변경을 복원하므로 재생성이 가능합니다. 앞서 적용된 GM UI/검선 패치는 유지합니다. pefile, capstone, keystone-engine, unicorn이 필요합니다. 설치는 별도이며 `validation.json`의 `installed: false`는 스테이징 시험을 뜻합니다. 실제 로컬 설치 해시는 `tests/results/client-install.json`에 있습니다.

현재 검증은 실제 x86 명령어 에뮬레이션 289개입니다. 전체 패킷 처리 함수 30개 입력, DLL 두 로드 주소, 구매 요청 직렬화, 수량 0/1/99/255/256/999/9999, 진단 DLL 초기화 성공/실패 경로를 포함합니다. `tests/results/stacks-live.json`은 별도 비운영자 계정으로 실제 서버의 구매·드롭 줍기·넘친 수량·마지막 카드 소비·강화·포션 사용·창고·재접속을 검증합니다.

실행 파일의 WinMain 호출 직전에 로컬 진단 DLL도 초기화합니다. 이는 수량 처리와 독립적이며 DLL/내보내기 함수가 없으면 원래 WinMain으로 계속 진행합니다. 자세한 내용은 `src/client/diagnostics/README.md`를 참고합니다.
