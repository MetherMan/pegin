# 카드 드롭의 고정 순서 편중 수정

타로스 계열 30개 몬스터 정의의 드롭 목록은 각각 26개이며, 로더가 목록 앞에 삽입하므로 카드 두 종류가 처음 두 칸에 놓인다. 기존 `GetMonsterItem`은 몬스터 종류별로 공유하는 `currDropItem`을 한 칸씩 이동했다. 따라서 카드 추첨은 1·2·27·28번째 처치에만 가능하고 그 사이 24번은 카드 후보 자체가 없었다. 30배는 카드가 후보로 선택된 뒤에만 적용된다. 기존 실행 파일에서 이 순서를 재현했다.

일반 몬스터는 매 처치마다 목록의 후보 하나를 균등하게 무작위 선택하도록 변경했다. 각 후보의 장기 평균 등장 비중, 카드 배수·상한, 일반 아이템의 확률, 아이템 생성·소유권·돈 대체 드롭 처리는 유지했다. 예를 들어 기본 카드 확률 33/1000인 이 목록은 추가 보너스가 없을 때 30배에서 합계 `2/26 × 990/1000 ≈ 7.615%`이다. 확률적 연속 미드롭은 여전히 가능하지만, 목록 순서 때문에 반드시 생기던 24회 공백과 시작 시 카드 집중은 제거했다. 이벤트 몬스터의 별도 드롭 경로는 변경하지 않았다.

맵 번호 변경만으로 기존 커서가 초기화되지는 않았다. 커서는 몬스터 종류별로 독립적이므로 종류가 바뀌면 다른 진행 위치를 사용하지만, 아버지 PC에서 맵 왕복 후 체감이 달라진 정확한 상황은 직접 재현하지 않았다. 시간이 지나면 카드 30배 설정이 감소하는 로직은 발견하지 못했다.

검증은 `tests/card_drop_test.py`와 `tests/results/card-drop.json`에 있다. 실제 i386 실행 파일의 후보 선택·카드 배수·난수 함수를 실행하고, 아이템 생성과 월드 배치는 경계에서 기록하는 오프라인 검사다. 30종의 후보 전체 선택, 배수 0·1·30·1000, 카드 축복과 일반 아이템 확률, 빈 목록·단일 항목, 62,400회 처치를 통과했다. 같은 난수 시작값에서 맵 번호와 구형 커서를 바꿔도 수정본의 결과는 동일하다. 실제 플레이어 전투 세션 검증은 아니다.

빌드는 CP949 원본 `src/server/LAQIA_GameServer/item.cpp`와 실제 빌드에 덮어쓰는 UTF-8 사본 `src/server/utf8/item.utf8.cpp`를 함께 반영한다. 총레벨 576 경험치 수정도 포함하며 기존 51개 경험치 검사를 다시 통과했다. 이 PC의 기존 `outputs/혼자 게임 시작.cmd` 설치본에 서버 실행 파일만 적용해 정상 시작과 저장 테이블·배수 보존을 확인했다. 결과는 `local-installation-validation.json` 및 `experience-regression.json`에 있다.

이번 변경은 커밋·푸시하지 않았다. 아버지 PC에는 아직 전달되지 않았으며, 나중에 다른 작업과 함께 기존 저장소에 푸시한 뒤 기존 업데이트 CMD로 받는 절차를 따른다.

재검사: Unicorn이 설치된 Python으로 저장소에서 실행한다. 별도 라이브러리 폴더는 `--deps 경로`, 수정 전 실행 파일 비교는 `--before 경로`를 추가한다.

```console
python tests/card_drop_test.py
```
