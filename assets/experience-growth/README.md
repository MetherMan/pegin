# 총레벨 576 경험치 정지 — 원인 재현 및 수정 완료

2026-09-23. 사용자 확인으로 아버지의 경험치 배수는 30배다. 사진의 근거리 151 / 원거리 147 / 흑마법 144 / 백마법 134와 타로스를 기준으로 재검사했다. 처음 제시한 1배 성장 속도 설명은 이번 정지의 원인이 아니다.

## 확정한 버그

`g_EXP_PROTECT`는 총레벨 0~400의 401바이트 표인데, 솔로 처치 처리 `CheckDeadMob`가 총레벨을 범위 확인 없이 인덱스로 사용했다. 수정 전 실행 파일에서 `g_EXP_PROTECT + 576` 주소는 정확히 `gWorldTime`과 같다.

게임 시간 단계가 1~6일 때 그 값을 경험치 계수로 잘못 읽고 정수 나눗셈 `/100`을 하므로 지급 경험치가 0이 된다. 그 뒤 30배를 곱해도 0이다. 시간 단계가 0일 때만 이 잘못된 감소 계산을 건너뛴다. 이 문제는 만렙 제한과 무관하다.

네 계열의 지급 경로 모두에 표 범위 확인을 추가했다. 표는 실제 경험치를 받는 캐릭터의 레벨로 조회한다. 구조체 크기, 기존 0~400 구간의 계산, 경험치 배수·요구량·최대 레벨은 바꾸지 않았다.

## 검증 및 적용

- 수정 전/후 실행 파일의 실제 x86 솔로 처치 함수를 30배로 비교했다. 시간 단계 7개 × 계열 4개에서 수정 전 0 경험치를 재현했고, 수정 후에는 모두 429,840을 지급했다. 추가 보너스 없이 일반 바포메트를 혼자 처치한 조건이다.
- 399·400·401·575·576·577·799 등 15개 경계 조건, 네 계열 실제 처치 후 레벨업 및 초과분 이월, 네 계열 200 제한을 포함해 총 51개 시나리오를 통과했다.
- 에뮬레이터에서는 경험치 계산·배수·누적·레벨업을 실제 코드로 실행하고, UI/네트워크/저장 알림과 드롭 등 부수 처리는 대체했다. 네이티브 게임 창으로 직접 사냥한 검사는 아니다.
- 이 PC의 원래 `outputs` 연결 설치본에 서버 실행 파일 하나를 백업 후 적용했다. 새 서버 시작과 접속 포트 검사를 통과했다. 캐릭터·인벤토리 등 저장 테이블 5개 해시가 전후 동일했고 경험치·카드 배수 설정도 동일했다. 검사 종료 후 서버를 정상 종료했다.
